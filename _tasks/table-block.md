# Задача: блок `table` — каталожная таблица моделей

**Ветка:** `work/table-block`
**Результат:** новый тип блока в `build.py` + стили в `assets/style.css` + поддержка в `check.py` + отчёт в `_log/`

## Зачем

Следующая страница — «Тяговые батареи». У линейки есть настоящий модельный ряд:
двадцать две модели в трёх группах по напряжению, у каждой артикул и ёмкость.
Абзацем это не подаётся, нужна таблица. Такие же таблицы понадобятся «Хранителю»
(девять конфигураций) и другим линейкам.

Это тот случай, когда новый тип блока заводить **нужно** — поэтому прошу тебя
сделать это прямо, а не выносить в отчёт, как велит общее правило.

## Как должно выглядеть в данных

```json
{
  "type": "table",
  "eyebrow": "Модельный ряд",
  "h2": "Подберите батарею",
  "h2q": "под свою технику",
  "lede": "…",
  "columns": [
    { "key": "model", "label": "Модель" },
    { "key": "cap",   "label": "Ёмкость", "align": "right", "mono": true },
    { "key": "note",  "label": "Примечание" }
  ],
  "groups": [
    {
      "title": "Линия 80 В",
      "rows": [
        { "model": "ЕОН-80В206-Т", "cap": "206 А·ч", "note": "" }
      ]
    }
  ]
}
```

- `groups` — необязательные. Если их нет, таблица принимает `rows` прямо в блоке.
- `columns` задаёт порядок и заголовки. `align: "right"` и `mono: true` — оформление
  колонки (моноширинный шрифт для артикулов и чисел, выравнивание вправо для величин).
- Значения ячеек — текст, разметка в них запрещена, как и везде.

## Как должно выглядеть на странице

- Шапка раздела — та же, что у остальных блоков, через `_head(b)`.
- Заголовок группы — отдельной строкой над своей частью таблицы, в стиле
  `.plate-head` (моноширинный, разрядка, прописные, серый).
- Строки с тонкой линией между ними, как в `.row` паспортной таблички.
  Числа — `font-variant-numeric: tabular-nums`, чтобы разряды стояли столбиком.
- **Обязательно: на узком экране таблица не должна расширять страницу.**
  Оберни её в контейнер с `overflow-x: auto`. Это единственное место на сайте,
  где горизонтальная прокрутка разрешена, — и только внутри контейнера,
  не у всей страницы.
- Тёмная подложка (`"dark": true`) должна работать, как у других блоков.

Цвета, шрифты и отступы бери **только из существующих токенов** в `:root`.
Новых токенов не заводи.

## Поддержка в проверке

В `check.py` новый тип должен попасть в `BLOCK_TYPES`, а его обязательные поля —
в проверку: нужны `columns` (непустой) и хотя бы одна строка. Отдельно стоит
ловить случай, когда в строке есть ключ, которого нет в `columns`, — такая ячейка
не отрисуется и пропадёт молча. Это ровно тот класс ошибки, который ты ловил
в прошлой задаче.

## Проверка

1. Собери пробную страницу с этим блоком — с группами и без, с тёмной подложкой
   и без, — убедись, что всё отрисовывается. Пробную страницу в ветку не коммить.
2. Проверь поведение на узком экране: страница не должна получать горизонтальную
   прокрутку. Как проверишь — опиши в отчёте, это важный пункт.
3. Контрольные поломки на новые проверки в `check.py`, как в прошлый раз.
4. `python3 check.py` на main-данных должен по-прежнему давать 0.
