# Задача: инструмент проверки сайта

**Ветка:** `work/check`
**Результат:** `check.py` в корне + встроен в сборку + отчёт в `_log/`

## Зачем

В ближайшие дни в `content/` появится полтора десятка новых страниц, написанных
руками. Битые ссылки, забытые якоря, пустые обязательные поля при таком объёме
неизбежны, а глазами их не выловить. Нужен скрипт, который ловит это за секунду
и не даёт влить сломанную ветку.

Это не формальность и не отчётность: им будут пользоваться каждый день.

**Сначала прочитай `CLAUDE.md` и `README.md`** — устройство сборки, формат данных
и правила. Посмотри `build.py` и готовые `content/index.json`, `content/guardian.json`.

## Что должен проверять

Собери сайт (`python3 build.py`) и проверь по готовому `dist/` и по данным:

1. **Сборка проходит.** `build.py` отрабатывает без исключений. Если падает —
   остальные проверки не запускаются, выводится сообщение об ошибке.
2. **Внутренние ссылки ведут на существующие страницы.** Каждый `href="что-то.html"`
   в собранных страницах — это файл, который реально есть в `dist/`.
   Выводить: на какой странице, в какой ссылке, куда ведёт.
3. **Якоря на месте.** Каждый `href="#якорь"` имеет соответствующий `id`
   на той же странице. Это уже один раз выстрелило на «Хранителе».
4. **Меню и подвал не врут.** Каждая страница, на которую ссылается `content/site.json`,
   существует в `content/`. Это поймает пункт меню, под который страницу ещё не написали.
5. **Обязательные поля заполнены.** У страницы — `title` и непустой `description`.
   У каждого типа блока — свой минимум; какие поля читает рендер, видно в `build.py`.
   Пустая строка считается незаполненным полем.
6. **В данных нет лишней разметки.** В текстовых полях разрешены только
   `&nbsp;`, `<br>` и `<em>` (см. README). Любой другой тег — ошибка:
   он либо не отрисуется, либо сломает вёрстку.
7. **Сайт закрыт от индексации.** На каждой собранной странице есть
   `noindex`, в `dist/robots.txt` есть `Disallow: /`. Эта проверка охраняет
   от случайного открытия сайта раньше времени — см. раздел «Состояние» в README.
   Когда придёт время открывать, проверку снимут намеренно.

## Как должен себя вести

- Запуск: `python3 check.py`, без аргументов, из корня репозитория.
- При ошибках — ненулевой код возврата. Это важно: по нему сборка в CI станет красной.
- Вывод человеку, а не машине: сгруппировать по страницам, по каждой ошибке сказать,
  **где** она и **что именно** не так. Представь, что читать будет уставший человек,
  который только что написал пятнадцать страниц.
- Стандартная библиотека Python, без зависимостей. Сборка и так ставит только Python.

## Встроить в сборку

В `.github/workflows/pages.yml` добавить запуск `check.py` **перед** сборкой сайта.
Красная проверка должна валить workflow. Это единственное место, где тебе
разрешено тронуть общий файл — и только эту строку.

## Проверка самой проверки

Скрипт, который ничего не находит, бесполезен и выглядит точно так же, как
рабочий. Поэтому: временно сломай что-нибудь в данных по каждому пункту
(битая ссылка, пропавший якорь, пустой `description`, лишний тег) и убедись,
что проверка это ловит и внятно сообщает. Потом верни данные как было.

В отчёте приведи, что именно ломал и как скрипт на это отреагировал.
Без этого работа не принимается — по той же причине, по которой не принимается
непроверенный перенос.
