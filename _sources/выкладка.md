# Как сайт попадает на сервер

Сборка живёт на GitHub, сайт — на своём сервере с nginx. Каждый push в `main`
запускает `.github/workflows/deploy.yml`: он проверяет сайт, собирает его
и копирует каталог `dist/` на сервер по SSH.

**В этом файле нет ни адресов, ни ключей, ни паролей** — репозиторий публичный.
Всё это лежит в секретах репозитория на GitHub, куда заглянуть может только
владелец.

---

## Что уже настроено (27.10.2026)

Настройка сервера и секретов сделана один раз, повторять её не нужно.
Здесь записано, что именно сделано, — чтобы это можно было восстановить,
если сервер придётся поднимать заново.

**На сервере.** Выкладка ходит под отдельным пользователем `deploy`
(не root), у него свой каталог ключей `/home/deploy/.ssh` с правами 700
и `authorized_keys` с правами 600. Каталог сайта —
`/var/www/eon-rus/public`, он принадлежит `deploy`. nginx для домена уже
был настроен отдельным конфигом, сертификат Let's Encrypt выпущен; трогать
их не понадобилось. SSH на штатном порту, вход по ключу разрешён, `rsync`
установлен.

**Ключ доступа.** Пара ключей `ed25519` с пометкой `github-actions-eon-rus`.
Открытая половина лежит в `authorized_keys` пользователя `deploy`, закрытая —
в секрете `DEPLOY_KEY` на GitHub и больше нигде.

**Секреты репозитория.** `Irina-IP-26/eon-rus` → Settings → Secrets and
variables → Actions:

| Имя секрета | Что в нём |
|---|---|
| `DEPLOY_HOST` | адрес сервера |
| `DEPLOY_USER` | `deploy` |
| `DEPLOY_PATH` | каталог сайта |
| `DEPLOY_KEY` | закрытая половина ключа, целиком, вместе со строками `-----BEGIN` и `-----END` |
| `DEPLOY_KNOWN_HOSTS` | отпечаток сервера: `ssh-keyscan -t ed25519 АДРЕС` |

Шестой, `DEPLOY_PORT`, нужен только если SSH слушает не 22-й порт. Сейчас
он не заведён и не нужен.

Сами значения здесь не повторяются намеренно: репозиторий публичный.
Адрес сервера виден в панели хостинга, остальное — в секретах.

### Если ключ придётся поменять

Старый убрать из `authorized_keys`, новый сделать и положить туда же,
закрытую половину переписать в секрет `DEPLOY_KEY`. Пароль root при этом
не нужен: на сервер можно зайти через консоль в панели хостинга.

## Как это работает дальше

Любое изменение, попавшее в `main`, само уезжает на сервер: проверка, сборка,
копирование, и в конце запрос к главной странице по адресу домена — если она
не ответила, выкладка считается неудачной и в GitHub загорается красный крест.

Копирование идёт с ключом `--delete`: файлов, которых больше нет в сборке,
не останется и на сервере. Поэтому **каталог в `DEPLOY_PATH` должен принадлежать
только этому сайту**. Если указать туда каталог с чем-то ещё, это «что-то ещё»
будет стёрто при первой же выкладке.

Сайт закрыт от поисковиков: `robots.txt` содержит `Disallow: /`, на каждой
странице стоит `noindex`. Снятие запрета — отдельный шаг перед выпуском,
он описан в `README.md`, и делается он не вместе с переездом.
