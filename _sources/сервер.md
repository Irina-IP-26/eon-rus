# Сервер компании

Что известно на 08.10.2026 — смотрел своими глазами в панели управления
по просьбе владельца.

**Намеренно без адресов и паролей.** Репозиторий публичный, и писать сюда
IP-адрес вместе со строкой «ssh root@…» означает выложить приглашение
перебирать пароли. Адреса — в панели Timeweb у владельца; сюда пишем только
то, что нужно для планирования.

## Что это

| | |
|---|---|
| Провайдер | Timeweb Cloud, российский |
| Тип | облачный сервер (виртуальный), не shared-хостинг |
| Название в панели | «Сайтики» |
| Операционная система | Ubuntu 26.04 |
| Процессор и память | 2 ядра 3,3 ГГц, 4 ГБ |
| Диск | 50 ГБ NVMe, занято 3,5 ГБ |
| Канал | 1 Гбит/с |
| Доступ | SSH под root |
| Аптайм на момент осмотра | 21 день |

В панели рядом доступны, но не используются: базы данных как услуга,
хранилище S3, почта, домены и SSL, балансировщики.

## Что это значит для нас

**Можно всё, что мы откладывали.** До сих пор мы исходили из того, что сайт —
статика в публичном репозитории, и из этого следовали три ограничения,
записанные в `STATUS.md`: приёмник заявок невозможен без внешнего сервиса,
админка невозможна, закрытый раздел для партнёров невозможен. Все три
ограничения снимаются: это обычный Linux-сервер, на нём ставится что угодно.

- **Python есть или ставится одной командой.** Сайт собирается им же — значит
  приёмник заявок, админка и сборка живут на одном языке.
- **База данных** ставится на сам сервер либо берётся у провайдера отдельной
  услугой. Для админки и закрытого раздела этого достаточно с запасом.
- **Диск свободен на 93 %**, памяти 4 ГБ. Для сайта, приёмника заявок и базы
  это много; упереться можно разве что в тяжёлые фотографии, и то нескоро.

**Сайт тоже может переехать сюда.** Сейчас он на GitHub Pages, и это было
правильным решением для прототипа: бесплатно, быстро, без настройки. Но как
только появится админка, страницы перестанут быть просто файлами из гита,
и держать их отдельно от базы станет неудобно. Переезд не срочный и не
обязательный, но его стоит держать в голове как развилку.

## Python и база — можно, вопрос закрыт 09.10.2026

Владелец спросила прямо: можно ли на этом сервере ставить Python и базу,
а если нельзя — арендовать ли второй. Ответ: **можно, второй не нужен.**

Решает дело не страница тарифов, а то, что видно в панели: **Ubuntu 26.04
и вход по SSH под root.** Это обычная линуксовая машина целиком в нашем
распоряжении, а не виртуальный хостинг с разрешённым списком программ.
Timeweb подтверждает это с другой стороны: на облачный сервер разрешено
загрузить даже собственный образ «с любым ПО, которое необходимо для проекта».

- **Python** в Ubuntu 26.04 есть из коробки. Сайт собирается им же — значит
  сборка, приёмник заявок и админка будут на одном языке.
- **PostgreSQL** ставится одной командой `apt install postgresql`.
- **Либо управляемая база у Timeweb** отдельной услугой: PostgreSQL, MySQL,
  MongoDB, ClickHouse, от 180–790 ₽ в месяц смотря по конфигурации. Плюс —
  обновления и резервные копии на провайдере. Минус — платим за то, что
  на своём сервере уже оплачено. Для нашей нагрузки свой PostgreSQL дешевле
  и достаточен; к управляемой базе имеет смысл вернуться, если данных станет
  много или понадобится, чтобы падение сайта не уносило базу с собой.
- **Ресурсов хватает с огромным запасом:** занято 3,5 ГБ из 50, памяти 4 ГБ.
  Сайт, приёмник заявок и база — единицы процентов такой машины.

## Битрикс24 — коробочный, на отдельном сервере

Выяснено 09.10.2026. Два следствия, оба хорошие:

1. **Данные заявок не покидают инфраструктуру компании.** В цепочке
   «форма → наш приёмник → Битрикс» нет ни одного внешнего сервиса, значит
   152-ФЗ закрывается сам собой и политику обработки данных переписывать
   не придётся.
2. **Память «Сайтиков» наша целиком.** Коробочный Битрикс любит 4 ГБ и больше;
   если бы он стоял здесь же, нам было бы тесно. Он не здесь.

Открытый вопрос: видят ли два сервера друг друга по сети. Если у Битрикса есть
публичный адрес — вопроса нет, вебхук зовётся по нему как обычная ссылка.

## Что надо сделать до того, как ставить сюда что-то наше

1. **Разобраться, что на сервере уже есть.** Там лежат другие сайты компании,
   и первым делом нужно посмотреть, что именно, чтобы ничего не задеть.
2. **Закрыть вход по паролю под root.** Сейчас в панели выдан root-пароль,
   то есть вход по паролю открыт. Сервер с белым адресом перебирают
   круглосуточно, это фон интернета. Нормальная практика: вход по ключу,
   пароль отключён, root напрямую не пускается. Это получасовая работа,
   и делать её надо **до** того, как на сервере появится приёмник заявок
   с персональными данными.
3. **Отдельный пользователь и отдельная база для каждого дела.** Владелец сама
   сформулировала это требование раньше, в другом разговоре: чтобы взлом сайта
   не давал доступа к данным. Значит сайт, приёмник заявок и будущая программа
   разбора почты не должны ходить друг к другу в гости.
