## Часть 1. Поле `lineup`

**Что делает.** Для страницы P с `"lineup": "Q"` модельный ряд — это таблицы с `bounds`
страницы Q **плюс** свои таблицы с `bounds` у P, если они есть. Значения одной единицы
складываются, строки — тоже. Тексты, которые относятся к P по ссылке (карточка
на главной, подзаголовок меню), автоматически попадают под тот же модельный ряд:
одно поле — пять мест.

**Ошибки:**

| Случай | Сообщение |
|---|---|
| страницы нет | `lineup = «guardian-lineupp» — такой страницы нет (нужен content/guardian-lineupp.json)` |
| у страницы нет колонки с `bounds` | `lineup = «energyflow» — на странице energyflow нет ни одной колонки с "bounds": true; связь выглядит рабочей, а сверять не с чем` |
| на саму себя | `lineup = «guardian» — страница ссылается сама на себя; свои таблицы с bounds и так в силе, поле не нужно` |
| не строка | `lineup = True — нужно имя страницы модельного ряда, например "guardian-lineup"` |
| с `.html` | `lineup = «guardian-lineup.html» — имя страницы без .html: «guardian-lineup»` |

Последнее — моё добавление: одна форма записи вместо двух, чтобы поле не писали то так,
то эдак. Если страница из `lineup` есть, но её JSON не читается, отдельной ошибки нет —
о битом JSON уже сказано.

**Один уровень.** Если у страницы модельного ряда свой `lineup`, он для продающей страницы
не подтягивается (поломка L8). Модельный ряд — конечная точка.

**Источник в сообщениях.** Если текст сверен не со своей таблицей, это сказано:
«по таблице страницы guardian-lineup.html», а при сложении — «по таблице страницы
guardian.html, guardian-lineup.html».

**README** — раздел про `lineup` рядом с `bounds`: что значит, когда нужно, почему
объявляет продающая страница, что складывается, а не подменяется, и какие бывают ошибки.

## Часть 2. Счёт модельного ряда

**Что считается модельным рядом:** все таблицы с колонкой `bounds` — своей страницы
и через `lineup`. Таблица без отметки (батарейные модули на `guardian-lineup`, 8 строк)
в счёт не идёт — поломка C10. Отдельной отметки не завёл: `bounds` уже значит «это и есть
модельный ряд», вторая отметка ничего бы не добавила, а забыть её было бы легко.

**Что считается счётом:** число от 2 до 100 (цифрами или словами) и сразу после него —
одно из слов списка, между ними допускаются одно-два прилагательных:

- конфигурация, модель, позиция — во всех падежах.

Список — в README и в `check.py` (`COUNT_NOUNS`), дополняется одной строкой.
Не входят намеренно: «исполнение» (у «Хранителя» три исполнения — это корпуса),
«модуль» (у модулей своя таблица). Формы слова перечислены явно, а не по корню:
по корню «модел…» под счёт попал бы «модельный ряд».

**Числительные словами:** от двух до ста, с падежами — «шестнадцать», «из шестнадцати»,
«шестнадцатью», «двадцать две», «двадцати двух», «сорока», «ста». Составные — десятки
плюс единицы, в том числе «двадцать одна». «Один / одна» сами по себе — не счёт.

**Что видит на сегодняшних данных** — семь фраз, все сходятся:

| `guardian-lineup.json`, описание | «шестнадцать конфигураций» | своя таблица | 16 |
| `guardian-lineup.json`, лид | «шестнадцать серийных конфигураций» | своя таблица | 16 |

## Что не получилось

**Мой скрипт поломок испортил данные.** Скрипт из задачи про `PLANNED` в случае
«написанная страница осталась в списке» создавал временный `content/skif.json`, а после
прогона удалял его. Когда я его писал, страницы «Скиф» не было; сейчас она в `main`.
Скрипт перезаписал настоящий файл пробным и удалил. Заметил по `git status`
(`D content/skif.json`) и по тому, что следующие наборы получили красное исходное
состояние, — их результаты я выбросил. Файл восстановил `git checkout`, он совпадает
с `main`; в коммит удаление не попало. Скрипт исправил: теперь он берёт страницу,
которой точно нет (`damping` из `PLANNED`), и сохраняет-возвращает любой файл,
который уже был. Все наборы прогнал заново.

Урок, который стоит записать: **временный файл в `content/` не должен носить имя,
которое может появиться в проекте**, а откат должен возвращать прежнее содержимое,
а не удалять. Если сочтёте нужным — это строчка в `ГРАБЛИ.md`; сам туда не писал,
это ваш файл.

**Что проверка счёта не видит:**
- счёт в другом порядке: «конфигураций — шестнадцать», «модельный ряд из 22»;
- счёт без слова из списка: «22 батареи», «16 вариантов»;
- «один / одна» — не считается по договорённости.

## Что заметил по дороге и не трогал

- **Ошибки счёта и границ пишутся одним видом `[диапазон]`.** Для человека, который читает
  вывод, «в тексте 15, а строк 16» под ярлыком «диапазон» — не самое точное слово.
  Можно завести вид `[счёт]`; не стал без вас, это меняет вид вывода.
- На главной есть **две карточки со ссылкой на `guardian.html`**: в «Двух направлениях»
  и в «Серийных линейках». Обе относятся к «Хранителю», обе сверяются — это правильно,
  но о такой двойственности стоит знать тому, кто будет писать поломки (я споткнулся).
- `bounds_ignore` глушит оба правила сразу — границы и счёт. Отдельные выходы для каждого
  не делал: пока не видно фразы, где нужно заглушить одно и оставить другое.
