# еон.рус — сайт НПК Еон

Статический сайт, собираемый из данных. Содержание страниц лежит в `content/*.json`,
вёрстка — в `build.py`. Сборка кладёт готовые страницы в `dist/`, оттуда их
публикует GitHub Actions.

Так сделано намеренно: когда дойдём до админки, ей не придётся переписывать сайт —
она будет править те же `content/*.json`, а `build.py` станет её движком.
Если бы текст был вмурован в HTML, этот шаг пришлось бы начинать с нуля.

## Устройство

```
content/site.json      общее: шапка, меню, подвал, реквизиты, логотип
content/<страница>.json  содержание одной страницы
assets/style.css       все стили сайта
build.py               сборщик: данные + вёрстка → dist/
dist/                  результат сборки, в гит не коммитится
.github/workflows/     сборка и публикация при пуше в main
```

Сборка локально:

```
python3 build.py
```

Имя файла в `content/` задаёт адрес страницы: `guardian.json` → `guardian.html`.

## Страница

```json
{
  "title": "Заголовок во вкладке браузера",
  "description": "Описание для поисковой выдачи",
  "blocks": [ { "type": "hero", "...": "..." } ]
}
```

`blocks` — последовательность блоков сверху вниз. Тип блока определяет вёрстку.

## Типы блоков

| Тип | Назначение | Обязательные поля |
|---|---|---|
| `hero` | Первый экран | `eyebrow`, `h1`, `lede` |
| `figs` | Полоса цифр (3 или 4) | `items[{value, label}]` |
| `cards` | Сетка карточек | `items[{title}]`, `cols` |
| `points` | Список «термин — пояснение» | `items[{term, text}]` |
| `steps` | Нумерованные шаги | `items[{title, text}]` |
| `cases` | Карточки проектов | `items[{meta, title, text}]` |
| `plates` | Две паспортные таблички | `items[]` |
| `faq` | Раскрывающиеся вопросы | `items[{q, a}]` |
| `circuit` | Разделитель-дорожка платы | — |
| `form` | Форма заявки | `placeholder` |
| `table` | Каталожная таблица моделей | `columns[{key, label}]`, `groups[{title, rows}]` или `rows` |

Общие необязательные поля любого блока:

- `eyebrow`, `h2`, `h2q`, `lede` — шапка раздела. `h2q` — хвост заголовка, он уходит в серый.
- `dark` — раздел на тёмной сланцевой подложке.
- `tight` — убрать верхний отступ, когда раздел продолжает предыдущий.
- `id` — якорь раздела. Без него ссылка вида `#lineup` никуда не ведёт.

У `circuit` есть `symbols`: список из `saw`, `cap`, `dot` в нужном порядке.
По умолчанию рисуются все три.

В `cards` у карточки бывают `chip` (ярлычок), `chip_accent`, `spec` (моноширинная
строка характеристик), `link{href,label}`, `fill` (`accent` или `slate`).

### Таблица `table`

```json
{
  "type": "table",
  "eyebrow": "Модельный ряд", "h2": "Подберите батарею", "h2q": "под свою технику",
  "columns": [
    { "key": "model", "label": "Модель", "mono": true },
    { "key": "cap",   "label": "Ёмкость", "align": "right", "mono": true },
    { "key": "note",  "label": "Примечание" }
  ],
  "groups": [
    { "title": "Линия 80 В", "rows": [ { "model": "ЕОН-80В206-Т", "cap": "206 А·ч", "note": "" } ] }
  ]
}
```

- `columns` — порядок и заголовки колонок. `key` связывает колонку со значениями
  в строках, `label` — заголовок. `align: "right"` — выравнивание вправо (для величин),
  другого не бывает. `mono: true` — моноширинный шрифт без переноса (артикулы, числа).
  Колонка без `mono` считается текстовой: она переносится по словам и не сжимается
  уже 11em.
- `groups` — группы с заголовком (`title`) и строками (`rows`). Без групп строки
  кладутся прямо в блок, в `rows`. Одновременно `groups` и `rows` — ошибка.
- Строка — объект «ключ колонки → значение». Пустая строка `""` и отсутствующий ключ —
  пустая ячейка. Ключ, которого нет в `columns`, — ошибка: такая ячейка не отрисуется.
- Первая колонка — заголовок строки (`<th scope="row">`), обычно это модель.
- `bounds: true` у колонки — заявление автора данных: **минимум и максимум этой колонки —
  официальный диапазон линейки.** Тогда `check.py` сверяет с таблицей все тексты страницы
  (заголовок, описание, лиды, таблички, вопросы):
  - диапазон с той же единицей — «от 150 до 920 А·ч», «от 150 до 920 ампер-часов»,
    «150–920 А·ч» — обязан **совпадать** с минимумом и максимумом таблицы, а не попадать в них;
  - одиночное число с той же единицей обязано быть среди значений таблицы.

  Единица берётся из ячейки («206 А·ч») или из заголовка колонки после запятой
  («Ёмкость, А·ч» и голые числа в ячейках). Написания приводятся к одному виду:
  «А·ч», «Ач», «A·ч» с латинской A и «ампер-часов» — одна единица. Колонки без отметки
  не сверяются: на странице законно стоят «220 В», «3000 циклов», «36 месяцев».
  Каждая непустая ячейка колонки с `bounds` должна читаться как число с единицей.
- **Разметка в ячейках не работает никакая**, как бы ни называлась колонка:
  колонка `text` — такой же текст, как любая другая.
- На узком экране таблица прокручивается вбок внутри своей рамки; страница
  в ширину экрана остаётся. Это единственное место на сайте, где горизонтальная
  прокрутка разрешена.

## Журнал работ

`_log/` — отчёты по каждой задаче, которую вёл не человек. Отчёт пишется дословно,
без редактуры, и к нему приписывается, что из найденного было проверено и исправлено.
Нужен затем, чтобы работу можно было прочитать напрямую, а не в чьём-то пересказе.
В сборку `_log/` не попадает: `build.py` читает только `content/`.

## Правила, которые нельзя нарушать

1. **Тексты берутся с прототипа на тильде дословно.** Ничего не переписывать,
   не улучшать, не сокращать. Если в источнике опечатка — переносить как есть
   и записать её отдельно, а не чинить молча.
2. **Расхождения не исправляются по ходу.** Если одна страница говорит «5 кВт·ч»,
   а другая «2,5 кВт·ч» — обе переносятся как есть, расхождение выносится в отчёт.
   Решение о том, какая цифра верная, принимает владелец.
3. **Новых классов CSS не заводить.** Вёрстка собирается только из того, что уже
   есть в `assets/style.css`. Нужен новый приём — он обсуждается отдельно.
4. **Разметка в данных запрещена**, кроме `&nbsp;`, `<br>` и `<em>` в полях
   `lede`, `text`, `spec`, `a`, `h1`, `h1q`, `h2`, `h2q` и `v` (значение в
   паспортной табличке). Всё остальное экранируется.
5. **Структура раздела повторяет прототип**: тот же порядок блоков, те же
   заголовки, то же деление на карточки.

## Состояние

Сайт закрыт от индексации. Это сделано намеренно и снимается **одним отдельным
шагом плана** — предпоследним, после админки и SEO-правок, перед выпуском.

### Чек-лист открытия для индексации

Запреты зашиты ровно в трёх местах. Снимать все три разом, частично нельзя —
иначе получится сайт, который поисковик видит, но обходить не может, или наоборот.

1. `build.py`, шаблон `PAGE` — строка `<meta name="robots" content="noindex, nofollow">`.
   Удалить целиком либо заменить на `index, follow`.
2. `build.py`, функция `main()` — запись `robots.txt` с `Disallow: /`.
   Заменить на разрешающий вариант и дописать `Sitemap:`.
3. `content/site.json`, поле `draft` — полоса «макет, закрыт от индексации».
   К выпуску полосы быть не должно.

После снятия проверить на живом сайте: `/robots.txt` отдаёт разрешение,
в исходном коде любой страницы нет слова `noindex`.

Готовы: главная и «Хранитель». Остальные страницы переносятся с прототипа
на тильде по тем же правилам.
