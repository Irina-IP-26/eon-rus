# еон.рус — сайт НПК Еон

Статический сайт, собираемый из данных. Содержание страниц лежит в `content/*.json`,
вёрстка — в `build.py`. Сборка кладёт готовые страницы в `dist/`, оттуда их
публикует GitHub Actions.

Так сделано намеренно: когда дойдём до админки, ей не придётся переписывать сайт —
она будет править те же `content/*.json`, а `build.py` станет её движком.
Если бы текст был вмурован в HTML, этот шаг пришлось бы начинать с нуля.

## Устройство

```
content/site.json      общее: шапка, меню, подвал, реквизиты, логотип
content/<страница>.json  содержание одной страницы
assets/style.css       все стили сайта
build.py               сборщик: данные + вёрстка → dist/
dist/                  результат сборки, в гит не коммитится
.github/workflows/     сборка и публикация при пуше в main
```

Сборка локально:

```
python3 build.py
```

Имя файла в `content/` задаёт адрес страницы: `guardian.json` → `guardian.html`.

## Страница

```json
{
  "title": "Заголовок во вкладке браузера",
  "description": "Описание для поисковой выдачи",
  "blocks": [ { "type": "hero", "...": "..." } ]
}
```

`blocks` — последовательность блоков сверху вниз. Тип блока определяет вёрстку.

## Закрытый раздел для партнёров — требование к архитектуре

Планируется раздел с партнёрскими ценами, куда попадают только после ручной
проверки. Данные для него есть: три уровня цен со скидками, условия их
предоставления, себестоимость, наценки.

**На нынешней конструкции такой раздел сделать нельзя, и это не вопрос
аккуратности.** Сайт собирается из публичного репозитория в статические файлы,
поэтому любые данные попадают сразу в два открытых места:

1. в `dist/`, который раздаётся всем, — файл доступен по прямому адресу,
   даже если ссылки на него нигде нет;
2. в историю гита, которая публична и необратима: удалить файл можно,
   удалить запись о нём — нет.

Пароль на странице прячет страницу, а не данные. Проверка «ручная» тем более
не помогает: она про то, кому дать ссылку, а не про то, кто может прочитать файл.

**Что для этого нужно на самом деле:**

- данные партнёрских цен **не должны попадать в этот репозиторий вообще**;
- они живут за сервером с проверкой прав — то есть это этап админки и базы
  данных, шаг 6 плана, а не правка вёрстки;
- либо отдельный приватный репозиторий и отдельная сборка, которая публикуется
  не сюда.

До этого момента в репозитории лежат **только розничные цены из колонки «САЙТ»** —
те, что и так показываются каждому посетителю. Себестоимость, наценки,
партнёрские уровни и «Оплата ЕОНУ» сюда не кладутся ни в каком виде,
включая черновики, задания и отчёты.

## Два типа товарных страниц

Товарные линейки устроены по-разному, и из этого следует разная структура страниц.
Это не оформление, а условие поискового продвижения: **продвинуть можно только
страницу, у которой есть собственный адрес.** Раздел внутри страницы, даже
с якорем, собственного адреса не имеет и в выдаче отдельно не живёт.

### Линейка сформирована → две страницы

Когда линейка сложилась: есть отдельные товары с чёткими характеристиками,
у каждого заранее определённая цена. Пример — **Хранитель**.

| Страница | Что на ней | Кто на неё приходит |
|---|---|---|
| `guardian.html` | продающая: задача покупателя, как работает, исполнения, вопросы | контекстная реклама и поиск |
| `guardian-lineup.html` | модельный ряд: модели, характеристики, цены | контекстная реклама и поиск |

Обе страницы продвигаются, на обе можно лить оба вида трафика. В герое
продающей страницы — две кнопки: заявка и переход на модельный ряд.

### Линейка не сформирована → одна страница

Когда товар делается под заказ и заранее определённого ряда не существует.
Пример — **тяговые батареи для складской техники**: видов техники много
(тележки, штабелёры, погрузчики), производителей много (Clark, Linde и другие),
у каждого по десять-двадцать моделей только штабелёров, плюс снятые
с производства машины, которые ещё ездят. Батарея проектируется под посадочное
место конкретной машины.

То, что на akb-eon.ru названо модельным рядом, — **усреднение, диапазон
мощностей, а не линейка.** Выдавать его за модельный ряд нельзя.

Поэтому отдельной страницы модельного ряда здесь нет, и вторая кнопка в герое —
не «Модельный ряд», а **«Отправить запрос»**.

### Как понять, какой случай перед тобой

Спроси: можно ли назвать товар артикулом и ценой, не зная, к какой машине
или объекту он поедет? Можно — линейка сформирована, нужна вторая страница.
Нельзя — одна страница и заявка.

## Куда класть фотографии

Файлы снимков — в `assets/img/`. В данных путь пишется от корня сайта,
без `assets`: `"src": "img/guardian-shchitok.jpg"`.

Сборка копирует `assets/` целиком, вместе с подпапками, так что никакой
регистрации нового файла не требуется: положил снимок — он на сайте.
Пустой слот (`"src": ""`) рисуется подписанной заглушкой с текстом из поля
`need`, где сказано, какой именно кадр нужен. Найти все такие слоты:
`grep -rn '"src": ""' content/`.

Проверка следит, что файл из `src` действительно существует, и выводит
вес каждой картинки.

## Типы блоков

| Тип | Назначение | Обязательные поля |
|---|---|---|
| `hero` | Первый экран | `eyebrow`, `h1`, `lede` |
| `figs` | Полоса цифр (3 или 4) | `items[{value, label}]` |
| `cards` | Сетка карточек | `items[{title}]`, `cols` |
| `points` | Список «термин — пояснение» | `items[{term, text}]` |
| `steps` | Нумерованные шаги | `items[{title, text}]` |
| `cases` | Карточки проектов | `items[{meta, title, text}]` |
| `plates` | Две паспортные таблички | `items[]` |
| `faq` | Раскрывающиеся вопросы | `items[{q, a}]` |
| `circuit` | Разделитель-дорожка платы | — |
| `form` | Форма заявки | `placeholder` |
| `doc` | Длинный юридический текст: оферта, политика |
| `table` | Каталожная таблица моделей | `columns[{key, label}]`, `groups[{title, rows}]` или `rows` |

Общие необязательные поля любого блока:

- `eyebrow`, `h2`, `h2q`, `lede` — шапка раздела. `h2q` — хвост заголовка, он уходит в серый.
- `dark` — раздел на тёмной сланцевой подложке.
- `tight` — убрать верхний отступ, когда раздел продолжает предыдущий.
- `id` — якорь раздела. Без него ссылка вида `#lineup` никуда не ведёт.

У `doc` есть `meta` (строка над текстом: город и редакция) и `sections` —
список разделов вида `{h, items}`, где `h` — заголовок раздела, а `items` —
абзацы. Блок заведён для оферты и политики: ни карточки, ни таблички договор
не держат, а резать его на блоки — значит потерять сквозную нумерацию пунктов.
Текст идёт в одну колонку шириной около 74 знаков, как в книге.

У `circuit` есть `symbols`: список из `saw`, `cap`, `dot` в нужном порядке.
По умолчанию рисуются все три.

В `cards` у карточки бывают `chip` (ярлычок), `chip_accent`, `spec` (моноширинная
строка характеристик), `link{href,label}`, `fill` (`accent` или `slate`).

### Таблица `table`

```json
{
  "type": "table",
  "eyebrow": "Модельный ряд", "h2": "Подберите батарею", "h2q": "под свою технику",
  "columns": [
    { "key": "model", "label": "Модель", "mono": true },
    { "key": "cap",   "label": "Ёмкость", "align": "right", "mono": true },
    { "key": "note",  "label": "Примечание" }
  ],
  "groups": [
    { "title": "Линия 80 В", "rows": [ { "model": "ЕОН-80В206-Т", "cap": "206 А·ч", "note": "" } ] }
  ]
}
```

- `columns` — порядок и заголовки колонок. `key` связывает колонку со значениями
  в строках, `label` — заголовок. `align: "right"` — выравнивание вправо (для величин),
  другого не бывает. `mono: true` — моноширинный шрифт без переноса (артикулы, числа).
  Колонка без `mono` считается текстовой: она переносится по словам и не сжимается
  уже 11em.
- `groups` — группы с заголовком (`title`) и строками (`rows`). Без групп строки
  кладутся прямо в блок, в `rows`. Одновременно `groups` и `rows` — ошибка.
- Строка — объект «ключ колонки → значение». Пустая строка `""` и отсутствующий ключ —
  пустая ячейка. Ключ, которого нет в `columns`, — ошибка: такая ячейка не отрисуется.
- Первая колонка — заголовок строки (`<th scope="row">`), обычно это модель.
- `bounds: true` у колонки — заявление автора данных: **минимум и максимум этой колонки —
  официальный диапазон линейки.** Тогда `check.py` сверяет с таблицей все тексты страницы
  (заголовок, описание, лиды, таблички, вопросы):
  - диапазон с той же единицей — «от 150 до 920 А·ч», «от 150 до 920 ампер-часов»,
    «150–920 А·ч» — обязан **совпадать** с минимумом и максимумом таблицы, а не попадать в них;
  - одиночное число с той же единицей — смотря по тому, что оно заявляет:

    | Форма | Что заявляет | Чему обязано равняться |
    |---|---|---|
    | «до N ед.» (без «от» перед ним) | верх линейки | максимуму таблицы |
    | «от N ед.» (без «до» после) | низ линейки | минимуму таблицы |
    | «N+ ед.», «свыше N ед.», «более N ед.» | верх линейки | максимуму таблицы |
    | любое другое: «206 А·ч», «модель на 450 А·ч» | конкретное изделие | одному из значений таблицы |

    **«не более N» и «не менее N» — не заявления о краях**, а обещание на каждое изделие:
    «ресурс не менее 3000 циклов» значит «ни одна батарея не хуже», а не «самая маленькая —
    3000». Такое число проверяется как обычное: оно должно быть среди значений таблицы.
    Решено 08.10.2026; появится фраза, где «не более» действительно значит верх линейки, —
    вернуться к вопросу, а не ставить на неё `bounds_ignore` молча.

  Единица берётся из ячейки («206 А·ч») или из заголовка колонки после запятой
  («Ёмкость, А·ч» и голые числа в ячейках). Написания приводятся к одному виду:
  «А·ч», «Ач», «A·ч» с латинской A и «ампер-часов» — одна единица. Колонки без отметки
  не сверяются: на странице законно стоят «220 В», «3000 циклов», «36 месяцев».
  Каждая непустая ячейка колонки с `bounds` должна читаться как число с единицей.

- **`"bounds_ignore": true`** у блока или элемента (карточки, строки таблички, вопроса FAQ,
  пункта меню) — выход для законной фразы, где число с единицей линейки стоит не про неё.
  Внутри него правила границ не проверяются; все остальные проверки работают как обычно.

  ```json
  { "q": "Чем заменить свинцовую батарею?",
    "a": "Свинцовая на 500 А·ч заменяется нашей на 480 А·ч.",
    "bounds_ignore": true }
  ```

  Без отметки «500 А·ч» — ошибка: такой модели нет. Отметка ставится на самый маленький
  объект, который содержит фразу, — не на блок целиком, если хватает одного вопроса.
  Значение не `true` — ошибка. **Отметка, которая ничего не глушит, — тоже ошибка:**
  без неё там и так чисто, а оставленная «на всякий случай», она однажды прикроет
  настоящее расхождение.

- **Межстраничная сверка по ссылке.** Текст относится к странице, на которую ведёт ссылка
  его объекта: карточка с `link.href`, пункт меню с `href` и `sub`, табличка с `button.href`.
  Такой текст сверяется с таблицей той страницы, а не своей. Подзаголовок меню
  «24 · 48 · 80 В, 150–920 А·ч» у `forklift.html` сверяется с таблицей «Тяговых»;
  карточка «Энергопотока» на любой странице — с таблицей «Энергопотока» (а пока её нет —
  не сверяется вовсе). Ссылка на свою же страницу (`#lineup`) текст никуда не переносит,
  ссылки внутри списков (кнопки `cta` героя) — тоже.
- **`"lineup": "<страница>"`** — поле на уровне продающей страницы (рядом с `title`):
  «границы и состав моего модельного ряда — в таблице этой страницы».

  ```json
  // content/guardian.json
  { "title": "…", "description": "…", "lineup": "guardian-lineup", "blocks": [ … ] }
  ```

  Нужно, когда линейка сформирована и модельный ряд вынесен на свою страницу
  (см. «Два типа товарных страниц»): продающая страница говорит «от 2,5 до 66 кВт·ч»
  и «шестнадцать конфигураций», а таблицы у неё нет. С полем `lineup` её тексты —
  и тексты, которые относятся к ней по ссылке (карточка на главной, подзаголовок меню), —
  сверяются с таблицей модельного ряда.

  **Объявляет продающая страница, а не модельный ряд**: отстают её тексты, и именно
  она на них ссылается; модельный ряд про продающие страницы знать не должен.
  Свои таблицы с `bounds` у продающей страницы тоже остаются в силе — значения
  складываются, а не подменяются. Действует на один уровень: `lineup` страницы
  модельного ряда не подтягивается дальше. Ошибка: страницы нет; на ней нет
  колонки с `bounds`; страница указывает сама на себя; имя с `.html`.
  `build.py` поле не читает — на собранную страницу оно не влияет.

- **Счёт модельного ряда.** «16 конфигураций», «шестнадцать конфигураций»,
  «двадцать две серийные модели» — число обязано равняться числу строк модельного ряда
  страницы, к которой относится текст (своей, через `lineup` или по ссылке).
  Модельный ряд — все таблицы с колонкой `bounds`; таблица без отметки (батарейные модули
  рядом с конфигурациями) в счёт не идёт.

  Слова, после которых число считается счётом модельного ряда (во всех падежах;
  между числом и словом допускается одно-два прилагательных — «22 **серийные** модели»):

  - конфигурация
  - модель
  - позиция

  Список дополняется в `check.py`, `COUNT_NOUNS`. **Не входят намеренно:**
  «исполнение» — у «Хранителя» три исполнения, это корпуса, а не строки ряда;
  «модуль» — у модулей своя таблица. Числа от 2 до 100, цифрами и словами
  («шестнадцать», «из шестнадцати», «двадцать две», «двадцати двух»).
  «один / одна» не считается: «одна модель покрывает весь склад» — оборот речи, не счёт.
  Гасится тем же `bounds_ignore`.
- **Разметка в ячейках не работает никакая**, как бы ни называлась колонка:
  колонка `text` — такой же текст, как любая другая.
- На узком экране таблица прокручивается вбок внутри своей рамки; страница
  в ширину экрана остаётся. Это единственное место на сайте, где горизонтальная
  прокрутка разрешена.

## Проверка собранных страниц

`check.py` после сборки читает `dist/` — то, что получат покупатель и поисковик.

**Сначала — что `dist/` свежий.** Набор страниц в `dist/` обязан совпадать с `content/`
(у каждой страницы есть свой `.html`, лишних нет), и каждый `.html` обязан быть создан
в этом же запуске. Иначе проверки по готовым страницам не запускаются вовсе: проверить
старое и сказать «чисто» хуже, чем не проверить.

| Что | Правило | Вид |
|---|---|---|
| Заголовки | ровно один `h1` на странице; в содержании (между шапкой и подвалом) уровни не прыгают через ступень; пустых заголовков нет | ошибка `[заголовки]` |
| Картинки | файл из `src` есть в `dist/` (то есть лежит в `assets/` по тому же пути); у каждого `<img>` непустой `alt` (пустые слоты рисуются без `<img>` — их это не касается) | ошибка `[картинки]` |
| Ссылки | нет `href=""`, `href="#"`, `javascript:`; у ссылки есть текст длиннее одного знака (стрелки не считаются) или `aria-label` | ошибка `[ссылка]` |
| `id` | каждый `id` на странице один | ошибка `[якорь]` |
| `title`, `description` | есть и не пустые | ошибка `[поле]` |
| | не повторяются между страницами | ошибка `[повтор]` |
| | `title` 30–70 знаков, `description` 70–200 знаков | предупреждение `[поиск]` |
| | почти повтор: у двух страниц общий кусок `title` или `description` целыми словами — не меньше двух слов и не меньше 60% более короткой строки | предупреждение `[поиск]` |

Длины считаются по видимому тексту: `&nbsp;` и `&amp;` — один знак. Длины — ориентир
выдачи, а не поломка страницы, поэтому предупреждение: сборку не валит.
Находки в шапке и подвале одинаковы на всех страницах и выводятся один раз,
в разделе `content/site.json`. В конце вывода — вес каждой страницы и каждой картинки.

Порог почти повтора — доля, а не число знаков: название категории («системы накопления
энергии») законно встречается в заголовках разных страниц, и абсолютный порог со временем
начал бы ругаться на него. Подбор порога — `_log/2026-10-08-картинки-и-поиск.md`.

## Журнал работ

`_log/` — отчёты по каждой задаче, которую вёл не человек. Отчёт пишется дословно,
без редактуры, и к нему приписывается, что из найденного было проверено и исправлено.
Нужен затем, чтобы работу можно было прочитать напрямую, а не в чьём-то пересказе.
В сборку `_log/` не попадает: `build.py` читает только `content/`.

## Правила, которые нельзя нарушать

1. **Тексты берутся с прототипа на тильде дословно.** Ничего не переписывать,
   не улучшать, не сокращать. Если в источнике опечатка — переносить как есть
   и записать её отдельно, а не чинить молча.
2. **Расхождения не исправляются по ходу.** Если одна страница говорит «5 кВт·ч»,
   а другая «2,5 кВт·ч» — обе переносятся как есть, расхождение выносится в отчёт.
   Решение о том, какая цифра верная, принимает владелец.
3. **Новых классов CSS не заводить.** Вёрстка собирается только из того, что уже
   есть в `assets/style.css`. Нужен новый приём — он обсуждается отдельно.
4. **Разметка в данных запрещена**, кроме `&nbsp;`, `<br>` и `<em>` в полях
   `lede`, `text`, `spec`, `a`, `h1`, `h1q`, `h2`, `h2q` и `v` (значение в
   паспортной табличке). Всё остальное экранируется.
5. **Структура раздела повторяет прототип**: тот же порядок блоков, те же
   заголовки, то же деление на карточки.

## Состояние

Сайт закрыт от индексации. Это сделано намеренно и снимается **одним отдельным
шагом плана** — предпоследним, после админки и SEO-правок, перед выпуском.

### Чек-лист открытия для индексации

Запреты зашиты ровно в трёх местах. Снимать все три разом, частично нельзя —
иначе получится сайт, который поисковик видит, но обходить не может, или наоборот.

1. `build.py`, шаблон `PAGE` — строка `<meta name="robots" content="noindex, nofollow">`.
   Удалить целиком либо заменить на `index, follow`.
2. `build.py`, функция `main()` — запись `robots.txt` с `Disallow: /`.
   Заменить на разрешающий вариант и дописать `Sitemap:`.
3. `content/site.json`, поле `draft` — полоса «макет, закрыт от индексации».
   К выпуску полосы быть не должно.

После снятия проверить на живом сайте: `/robots.txt` отдаёт разрешение,
в исходном коде любой страницы нет слова `noindex`.

**Раньше этого шага — ещё один, и он важнее.** Файл `ПРОВЕРИТЬ.md` должен быть
пуст. Пока он не пуст, на сайте стоят числа, за которые никто не поручился,
и открывать такой сайт поисковику рано: непроверенное число, которое никто
не видел, — это черновик, а то же число в выдаче — уже обещание покупателю.

Готовы: главная и «Хранитель». Остальные страницы переносятся с прототипа
на тильде по тем же правилам.
